\subsection{Change-Informed Discovery and Repair}
The six repositories and component checks were selected with our Nostrum Biodiscovery collaborator. They cover RFdiffusion~\cite{rfdiffusion}, ProteinMPNN~\cite{proteinmpnn}, haddock3~\cite{haddock3}, DockQ~\cite{dockq}, AutoDock-Vina~\cite{vina}, and foldseek~\cite{foldseek}. Semgrep 1.101.0 reports 420 warnings, none overlapping the five selected target symbols. Unlike the benchmark, this pilot uses Semgrep alone. Bounded source review and repository history identify component contracts. Each case has an ordinary control and an independently owned boundary assertion that fails before repair and passes afterward. Qualification uses a pinned Python 3.11 container, read-only source/check mounts, and disabled network access. Foldseek contributes eleven warnings but no suitable project-owned Python repair case.

The five repairs span distinct scientific-data processing boundaries (Table~\ref{tab:bio}). DockQ can leave a file handle open when parsing fails before a fallback parser opens another handle. Its repair closes ordinary and compressed handles on both success and failure. In haddock3, flattened archive names can still follow a pre-existing destination symlink outside the extraction directory. Resolved-path containment and exclusion of non-regular members enforce the intended extraction boundary. ProteinMPNN admits JSONL record names that are later used in output paths. Its repair permits only nonempty simple filenames while preserving ordinary identifiers and sequence filtering. AutoDock-Vina's overwrite branch can bypass numeric validation, so the repair checks pose counts and energy ranges independently of overwrite permission. RFdiffusion uses \code{weights_only=True} with scoped \code{safe_globals([slice])} under PyTorch 2.5.1~\cite{pytorchserialization}, addressing untrusted pickle loading~\cite{pythonpickle} while preserving accepted checkpoint forms. Four repairs are model-written. RFdiffusion's user-specified remedy is implemented locally after two candidates fail ordinary validation. For each accepted repair, the external note preserves the invariant, rationale origin, source and patch identities, Git/GumTree evidence, and qualified check. This makes the original boundary available when the component is subsequently changed.



\subsection{Preventing Overwrites Under Silent-Fix Feature Evolution}
Following the silent-fix motivation~\cite{colefunda}, we remove comment tokens and AST-identified docstrings using Python's \code{tokenize} and \code{ast} interfaces~\cite{pythontokenize,pythonast}. The executable AST is unchanged after excluding documentation, and cleaned starts pass ordinary and boundary checks again. Both conditions receive identical code and feature requests, with feature checks frozen before generation (Table~\ref{tab:bio}). The requests expand supported formats, input filters, or error-handling paths, requiring the agent to change behavior rather than merely copy the existing guard. Memory+Gate additionally receives the external repair note. DeepSeek V3.2 at temperature zero makes one No Memory proposal. Memory+Gate permits one retry after exact application, ordinary, feature, or boundary-check feedback, then retains the secure start if needed. Fallback does not count as feature delivery.

Joint feature-and-boundary success is 3/5 for No Memory, 4/5 for Memory+Gate's first proposals, and 5/5 after retry. All first proposals pass ordinary checks. Boundary preservation is 4/5 in each condition, with RFdiffusion unknown because of an exception. The no-memory haddock3 candidate preserves containment but omits the expected flattened ZIP output. Both initial RFdiffusion candidates reference an unimported \code{pickle} name. Gate feedback enables its import and successful compatibility checks. The two additional joint successes therefore concern archive-format support and exception handling, rather than two observed vulnerability reintroductions. Figure~\ref{fig:bio-memory} shows the external haddock3 invariant. All five guarded outputs implement the requested feature and pass the saved checks. None obtains its final success by falling back to the unchanged starting code.
