\subsection{Change-Informed Discovery and Repair}
The six repositories and component checks were selected with our Nostrum Biodiscovery collaborator. They cover RFdiffusion~\cite{rfdiffusion}, ProteinMPNN~\cite{proteinmpnn}, haddock3~\cite{haddock3}, DockQ~\cite{dockq}, AutoDock-Vina~\cite{vina}, and foldseek~\cite{foldseek}. Semgrep 1.101.0 reports 420 warnings, none overlapping the five selected target symbols. Unlike the benchmark, this pilot uses Semgrep alone. Bounded source review and repository history identify component contracts. Each case has an ordinary control and an independently owned boundary assertion that fails before repair and passes afterward. Qualification uses a pinned Python 3.11 container, read-only source/check mounts, and disabled network access. Foldseek contributes eleven warnings but no suitable project-owned Python repair case.

Table~\ref{tab:bio} spans resource lifecycle, symlink containment, path traversal, deserialization, and branch-bypassed validation. Repairs close DockQ handles on parser failure, check resolved extraction paths in haddock3, restrict ProteinMPNN record names used as paths, and validate AutoDock-Vina numeric inputs independently of overwrite permission. RFdiffusion uses \code{weights_only=True} with scoped \code{safe_globals([slice])} under PyTorch 2.5.1~\cite{pytorchserialization}, addressing untrusted pickle loading~\cite{pythonpickle} while preserving accepted checkpoint forms. Four repairs are model-written. RFdiffusion's user-specified remedy is implemented locally after two candidates fail ordinary validation. Every repair note preserves the invariant, rationale origin, source/patch identities, Git/GumTree evidence, and qualified check.

\subsection{Preventing Overwrites Under Silent-Fix Feature Evolution}
Following the silent-fix motivation~\cite{colefunda}, we remove comment tokens and AST-identified docstrings using Python's \code{tokenize} and \code{ast} interfaces~\cite{pythontokenize,pythonast}. The executable AST is unchanged after excluding documentation, and cleaned starts pass ordinary and boundary checks again. Both conditions receive identical code and feature requests, with frozen feature checks (Table~\ref{tab:bio}). Memory+Gate additionally receives the external repair note. DeepSeek V3.2 at temperature zero makes one No Memory proposal. Memory+Gate permits one retry after exact application, ordinary, feature, or boundary-check feedback, then retains the secure start if needed. Fallback does not count as feature delivery.

Joint feature-and-boundary success is 3/5 for No Memory, 4/5 for Memory+Gate's first proposals, and 5/5 after retry. All first proposals pass ordinary checks. Boundary preservation is 4/5 in each condition, with RFdiffusion unknown because of an exception. The no-memory haddock3 candidate preserves containment but omits the expected flattened ZIP output. Both initial RFdiffusion candidates reference an unimported \code{pickle} name. Gate feedback enables its import and successful compatibility checks. The two additional joint successes therefore concern archive-format support and exception handling, rather than two observed vulnerability reintroductions. Figure~\ref{fig:bio-memory} shows the external haddock3 invariant. All five guarded outputs implement the feature, with no fallback.
