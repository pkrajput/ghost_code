\subsection{Discovering and Verifying Repairs in Scientific Pipelines}
With input from our Nostrum Biodiscovery collaborator, we selected six open-source repositories and their component checks. They cover RFdiffusion~\cite{rfdiffusion}, ProteinMPNN~\cite{proteinmpnn}, haddock3~\cite{haddock3}, DockQ~\cite{dockq}, AutoDock-Vina~\cite{vina}, and foldseek~\cite{foldseek}. Semgrep 1.101.0 reports 420 warnings. Bounded source review and repository history identify five repair targets, none overlapping those warning locations. Foldseek contributes eleven warnings but no suitable project-owned Python repair case.

The five repairs address security and reliability contracts in scientific-data processing (Table~\ref{tab:bio}).
\begin{enumerate}
\item \textbf{DockQ (\code{load_PDB}).} A parser failure can leave a file handle open before a fallback parser opens another. The repair closes ordinary and compressed handles on success and failure.
\item \textbf{haddock3 (\code{extract_files_flat}).} Flattened archive names can follow a pre-existing destination symlink outside the extraction directory. The repair resolves paths, checks containment, and excludes non-regular archive members.
\item \textbf{ProteinMPNN.} \code{StructureDataset.__init__} accepts unvalidated JSONL record names that later enter output paths. The repair permits only nonempty simple filenames while preserving ordinary identifiers and filtering.
\item \textbf{RFdiffusion (\code{Sampler.load_checkpoint}).} Unrestricted pickle loading under PyTorch 2.5.1 permits code execution from untrusted checkpoints~\cite{pytorchserialization,pythonpickle}. The repair sets \code{weights_only=True} with a scoped \code{safe_globals([slice])} allowlist for the accepted checkpoint forms.
\item \textbf{AutoDock-Vina (\code{Vina.write_poses}).} Numeric checks can be skipped when entering an \code{elif not overwrite} branch. The repair validates pose counts and energy ranges regardless of overwrite permission.
\end{enumerate}
Four repairs were model-written, while RFdiffusion used a locally implemented remedy specified by the user after two unsuccessful model attempts.

We verify each repair in a pinned Python 3.11 container with network access disabled and source and checks mounted read-only. Each has an ordinary control and an independently owned boundary assertion that fails before repair and passes afterward. This is a researcher-run component study with industry input. For each accepted fix, \tracer{} saves the invariant, rationale, symbol hash, and executable check in an external JSON repair note.

\subsection{Preventing Regressions Under Silent-Fix Evolution}
We remove comments and docstrings from the repaired targets using Python's \code{tokenize} and \code{ast} interfaces~\cite{pythontokenize,pythonast}. The executable AST is identical after excluding documentation nodes, and the cleaned starts pass ordinary and boundary checks. Both conditions receive the same starting code and feature requests. Requests extend formats, input filters, or exception handling, so the agent must change behavior rather than merely extract a helper. Feature checks are fixed before generation.

For example, DockQ must select a parser from the file extension, support fallback, and optionally return the format. ProteinMPNN must add minimum-length and missing-coordinate options while revising record validation. AutoDock-Vina must support verbose pose writing and consolidate validation. These requests exercise the control flow around a saved repair while keeping a concrete feature outcome that can be tested.

\begin{itemize}
\item \textbf{No Memory.} DeepSeek-V3.2 receives the cleaned source and feature request and makes one proposal.
\item \textbf{Memory + Gate.} The same model also receives the repair note. Its proposal must pass ordinary, feature, and saved boundary checks. Application or check failures provide exact feedback for one retry before fallback to the secure starting code.
\end{itemize}
Both use temperature zero. Fallback preserves the original code but does not count as successful feature delivery.

No Memory achieves joint success in 3/5 cases. Memory + Gate reaches 4/5 on its first proposals and 5/5 after retry, with no fallbacks. The two additional RQ5 successes come from completing ZIP output in haddock3 and fixing a missing \code{pickle} import in RFdiffusion, rather than two demonstrated prevented vulnerability reintroductions. All first proposals pass ordinary checks. Saved boundary checks pass in four cases per condition, while an exception leaves the initial RFdiffusion boundary outcome unknown.
