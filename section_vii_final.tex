\subsection{Repair Contracts and Independent Scope}
With input from our Nostrum Biodiscovery collaborator, we selected RFdiffusion~\cite{rfdiffusion}, ProteinMPNN~\cite{proteinmpnn}, haddock3~\cite{haddock3}, DockQ~\cite{dockq}, AutoDock-Vina~\cite{vina}, and foldseek~\cite{foldseek}. Semgrep 1.101.0 reports 420 warnings. Source and history review identify five Python repair targets outside those warning locations. Foldseek contributes eleven warnings but no suitable project-owned Python case.

The five verified component contracts are:
\begin{enumerate}[label=\arabic*.]
\item \textbf{DockQ (\code{load_PDB}).} A parser failure can leave a file handle open before a fallback parser opens another. The repair closes ordinary and compressed handles on success and failure.
\item \textbf{haddock3 (\code{extract_files_flat}).} Flattened archive names can follow a pre-existing destination symlink outside the extraction directory. The repair resolves paths, checks containment, and excludes non-regular archive members.
\item \textbf{ProteinMPNN.} \code{StructureDataset.__init__} accepts unvalidated JSONL record names that later enter output paths. The repair permits only nonempty simple filenames while preserving ordinary identifiers and filtering.
\item \textbf{RFdiffusion (\code{Sampler.load_checkpoint}).} Unrestricted pickle loading under PyTorch 2.5.1 permits code execution from untrusted checkpoints~\cite{pytorchserialization,pythonpickle}. The repair sets \code{weights_only=True} with a scoped \code{safe_globals([slice])} allowlist for the accepted checkpoint forms.
\item \textbf{AutoDock-Vina (\code{Vina.write_poses}).} Numeric checks can be skipped when entering an \code{elif not overwrite} branch. The repair validates pose counts and energy ranges regardless of overwrite permission.
\end{enumerate}
DockQ and AutoDock-Vina concern reliability contracts. Four repairs were model-written. RFdiffusion used a developer-specified remedy after two unsuccessful model attempts.

All five boundary assertions fail before repair and pass afterward, alongside ordinary-input controls. External notes record invariants, rationale, source identity, and checks. We remove comments and docstrings with \code{tokenize} and \code{ast}, preserve the executable AST, and reverify cleaned starts~\cite{pythontokenize,pythonast}.

\subsection{Equal-Budget Feature Evolution}
The ten tasks extend checkpoint compatibility, archive aliases, hierarchical names, in-memory pose output, and lazy parsing (Table~\ref{tab:bio}). This purposive stress sample spans five repository clusters and is independent of SusVibes.

Checks cover default and new modes. Each repaired start passes its old checks. An evaluator-written reference passes all checks, while a weakened reference delivers the feature but violates a boundary. Reference code is withheld from the model.

DeepSeek-V3.2 (temperature zero) receives cleaned source and feature requests. The $2\times2$ factorial varies repair memory and boundary feedback. Memory supplies the repair note and a prospective contract clarification. All conditions receive functional feedback, the same token budget, and at most one retry. Boundary feedback adds saved and extended checks. B0/B1 boundary checks run after generation, without affecting retries. All 40 cells are retained. Pinned offline containers run checks. The archive preserves the protocol and correction history.

FuncPass requires ordinary and feature checks. SecPass requires saved and extended boundary checks. JointPass requires both. Table~\ref{tab:bio} separates first and final proposals. Execution errors are unknown boundary outcomes, not violations. Fallback retains the repaired start and is not feature delivery.

\noindent\textbf{Functional feedback alone (B0).} B0 reaches 4/10 joint successes and accepts three contract-violating proposals. RFdiffusion enables unrestricted checkpoint loading with \code{weights_only=False}. Two ProteinMPNN proposals admit backslashes forbidden by the portable naming contract, without demonstrating Linux path traversal. Functional checks accept these proposals because their features work despite the boundary failures.

\noindent\textbf{Boundary gate alone (B2).} B2 accepts zero observed violations but reaches only 3/10 joint successes, with seven fallbacks. Without the repair note, the agent receives check failures but lacks the recorded guidance on reconciling the feature with the repaired contract. Rejection protects the boundary, but that feedback does not consistently produce a proposal satisfying both obligations.

\noindent\textbf{Memory alone (B1).} The note guides feature implementation within the repaired contract, yielding 8/10 joint successes. One accepted proposal still relaxes ProteinMPNN's default simple-name restriction. Functional checks alone cannot reject this naming violation, even when the note describes the intended contract.

\noindent\textbf{Memory and boundary feedback (B3).} Combining guidance with enforcement yields 9/10 joint successes and zero accepted contract violations. The gate rejects the remaining naming violation and safely retains the repaired starting code. Memory explains how to preserve the boundary, while executable feedback checks whether the proposal does so.

The five additional joint successes of B3 over B0 comprise one restricted-loading success, one portable-naming success, and three feature or execution fixes. Figure~\ref{fig:bio-memory} shows the deserialization contrast. B3 leads this cohort, but five selected repository clusters do not establish a population effect.
