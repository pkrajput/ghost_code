\section{Industrial Relevance and Practical Takeaways}
\label{sec:implications}
\subsection{Relevance to Industrial Software Engineering}
As engineering teams adopt coding agents to deliver multi-file pull requests, functional test suites alone do not guarantee safe releases. In both general software repositories and specialized scientific pipelines examined with Nostrum Biodiscovery, our cases expose unstated assumptions about upstream callers, file paths, or serialization formats. Static analyzers remain essential first-line defenses, yet their primary locations do not overlap the reference vulnerable symbol in over 80\% of admitted patches in our study. \tracer{} addresses two practical gaps in industrial CI/CD workflows. First, it uses the coding agent's development history and reasoning logs to focus code review on the symbols and assumptions introduced by a pull request. Second, it turns accepted security fixes into persistent JSON repair notes and executable boundary checks so future feature updates can be checked against earlier security work.

\subsection{Actionable Takeaways for Practitioner Pipelines}
\noindent\textbf{1) More historical context is not always better.}
The recorded-rationale configuration achieves more verified security passes than the combined AST-and-rationale configuration with both investigators. Context dilution is a possible explanation, rather than a mechanism established by this comparison. A focused rationale excerpt can point to the coding agent's assumption, such as trusting an upstream caller to sanitize input. It gives the investigator a specific claim to check against current code. Teams should preserve concise reasoning excerpts linked to modified symbols and retrieve evidence relevant to that claim. The practical goal is to explain a security obligation, not to fill the prompt with every available historical diff.

\noindent\textbf{2) Combine change tracking with static analysis.}
Symbol tracking raises review coverage from 13.4\% primary SAST overlap to 94.6\% plan inclusion. Review workflows can use modified symbols and their callers to define the scope, then use scanner findings and recorded assumptions as evidence within that scope. A warning can start an investigation, while a changed function without a warning can still merit review. Keeping these routes visible helps a team understand why a component was selected. Coverage creates an opportunity for diagnosis, rather than a verdict.

\noindent\textbf{3) Reserve validation capacity after the final edit.}
The recovery study finds usable candidates among edits discarded before validation. A dedicated final check prevents turn scheduling alone from losing a candidate. Exploratory tests and final acceptance serve different purposes, so exhausting one should not silently remove capacity for the other. Record candidate generation, retention, and completed evaluation separately so service interruptions do not require repeating model requests. The saved patch and its validation result should remain available for later inspection even when the proposed repair is rejected.

\noindent\textbf{4) Protect silent fixes with executable repair notes.}
A repair's purpose may no longer be apparent during later maintenance. Saving its invariant alongside an independently owned boundary check gives future feature proposals a reusable acceptance condition. This separates the explanation of a guard from comments that may disappear when a function is rewritten. When a requested feature changes the intended contract, the maintainer can review the saved invariant explicitly and decide whether it should change. Report feature delivery separately from retaining the unchanged secure version.

In a pull-request workflow, the repair note can accompany the changed symbol as review evidence. A failed boundary check identifies the earlier obligation that the update may violate. Reviewers can then inspect that obligation alongside the new requirement, rather than reconstructing the original repair from an isolated code guard.

\section{Threats to Validity}
\label{sec:threats}
\emph{Construct validity.} Reference-patch overlap measures review opportunity, and broad symbols or incidental edits can overstate diagnostic precision. SusVibes tests verify specified contracts rather than the absence of every vulnerability~\cite{susvibes,susvibesartifact,repairsurvey,overfitting}. Recorded rationale is a stated development trace, not a guaranteed account of internal reasoning~\cite{turpin,lanham}.

\emph{Internal validity.} Protocol development followed repeated inspection of failures, so individual engineering changes are not isolated interventions. Resumed execution preserves earlier completed revisions. The fifteen semantic reviews form a purposive, single-reviewer sample rather than a population estimate. The maintenance comparison evaluates a complete workflow, combining memory, boundary enforcement, and one feedback retry.

\emph{External validity.} Selection favors Python outputs with publisher-reported functional success. The 42 admissions without complete shared outcomes may differ in environment difficulty or provider reliability. Repeated tasks across generators and few security conversions limit precision. The scientific-software study covers five selected component repairs in public repositories and is researcher-run with industry input. Results do not establish effectiveness across other languages or production deployments.

\section{Related Work}
\subsection{Benchmarks and Security of Agent-Generated Code}
SWE-bench evaluates repository issue resolution~\cite{swebench}, while SusVibes separates functional and security outcomes for agent-generated changes~\cite{susvibes,susvibesartifact}. CVEfixes links historical vulnerabilities to fixing commits, and Vul4J provides reproducible vulnerabilities and triggering tests~\cite{cvefixes,vul4j}. SWE-agent supplies repository interaction interfaces~\cite{sweagent}, and ReAct interleaves explanations with actions~\cite{react}. These interfaces preserve evidence of how an agent navigates, edits, and tests a repository. \tracer{} studies how those recorded development explanations support subsequent investigation and maintenance. We review existing generated patches against the benchmark's security oracle.

\subsection{Static Analysis and LLM-Assisted Vulnerability Detection}
CodeQL and Semgrep supply static analysis findings~\cite{codeql,semgrep}. IRIS infers taint specifications~\cite{iris}, LLMDFA combines model reasoning with dataflow checks~\cite{llmdfa}, RepoAudit explores repository dataflows with memory and validation~\cite{repoaudit}, and PAGENT guides vulnerability-triggering inputs with program analysis~\cite{pagent}. While KNighter mines historical patches to synthesize checkers~\cite{knighter}, these approaches do not use the coding agent's own development trajectory and recorded rationale as investigation evidence. \tracer{} compares those evidence channels within a common guarded repair protocol. Its conditional runtime checks follow the same broader principle of grounding a suspected flaw in observable program behavior.

\subsection{Code Evolution, Silent Fixes, and Automated Program Repair}
GumTree computes structural edit scripts~\cite{gumtree,gumtree3}, ViolationTracker tracks warnings across revisions~\cite{violationtracker}, CoLeFunDa represents function changes to identify silent fixes~\cite{colefunda}, and FixMiner mines recurring repair patterns~\cite{fixminer}. InferFix uses analyzer guidance~\cite{inferfix}, ChatRepair uses conversational test feedback~\cite{chatrepair}, and RepairAgent autonomously inspects, edits, and tests code~\cite{repairagent}. Our evaluation additionally traces losses between supported diagnosis, patch retention, and verified repair.


\subsection{Persistent Memory and Continuous Software Evolution}
Reflexion stores verbal feedback in episodic memory~\cite{reflexion}, and Self-Refine iteratively critiques and refines outputs~\cite{selfrefine}. POSTURA maintains a security posture graph~\cite{postura}, while \emph{Undoing the Fix} explores deliberately elicited regressions under an AI-control setting~\cite{undoingfix}. \tracer{} pairs repair notes with independently owned executable checks and evaluates benign feature evolution against the saved contract.

\section{Conclusion}
\tracer{} connects symbol tracking, temporal AST evolution, and recorded agent rationale to security investigation and persistent maintenance evidence. Across 3,096 repair runs, symbol tracking includes reference vulnerable symbols in 94.6\% of review scopes, compared with 13.4\% primary SAST overlap. The recorded-rationale configuration achieves the highest shared-cohort SecPass counts with both investigators, reaching 76 with DeepSeek and 75 with Gemini from 68 original passes. Corresponding functional regressions are zero and one. The repair funnel distinguishes diagnostic, scheduling, semantic, and operational losses. In structural-biology components, persistent repair memory with a boundary gate and one retry improves joint feature and security check success from 3/5 to 5/5.
