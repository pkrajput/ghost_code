\subsection{Iterative Engineering Progression (v6--v12)}
To understand how protocol design affects repair losses (RQ4), we trace seven iterative development revisions of our workflow (\texttt{v6} through \texttt{v12}, where \texttt{v12} is the final released configuration evaluated in Section~\ref{sec:results}) across a fixed ten-case diagnostic cohort (Table~\ref{tab:engineering}, Panel~A). It contains nine initially insecure outputs and one secure Wagtail control. Both configurations retain ten functional passes throughout. Final C3 preserves the control and repairs three cases, compared with one repair for C0.

\noindent\textbf{Evidence fidelity (v6--v8).} Current-source citation binding, structured probe observations, and symmetric scanner-negative gates make assessments auditable. Preserving GumTree parent-subtree operations and normalizing fragments restores guard descriptions that were missing from added functions. Wagtail's downstream rendering contract nevertheless remains unresolved, showing that delivering the evidence does not itself identify the correct repair boundary.

\noindent\textbf{Boundary authorization (v9--v10).} Static invariant-gap and differential guard-bypass routes support diagnoses. The initial authorization protocol still demands consumer reads even when callers are already preloaded or the target enforces its own input contract. Recognizing these cases removes redundant requirements, after which RSA and LangChain convert in C3.

\noindent\textbf{Context and lifecycle completeness (v11--v12).} Deduplicating state and reserving context headroom prevents two previously observed packing aborts. Tracking execution within class spans and supplying lifecycle cues makes the relevant review obligations actionable and supports the third C3 repair, in Wagtail Forms. All twenty final qualification cells avoid repair errors, although C3 turn-limit endings rise from two to six across the progression.

\subsection{Stage-Level Investigation Funnel and Validation Scheduling}
Table~\ref{tab:engineering}, Panel B, follows four nested stages. S1 records a hypothesis on a reference symbol. S2 requires a supported assessment on such a symbol, and S3 additionally requires an edit to its reference file within the supported group. S4 retains only candidates with a nonempty final patch. DeepSeek C3 reaches 252/97/89/60 cells across S1--S4, with ten retained SecPass outcomes including six conversions. Gemini C3 reaches 235/23/21/17, with five passes and four conversions. These retained-subset counts differ from whole-campaign totals. The largest loss is between localization and support. Diagnostic trace review finds refutations, inconclusive assessments, overgeneralized hypotheses, and turn exhaustion alongside rejected positive actions. A reference location alone does not establish a defect, including on initially secure outputs.

A separate development recovery check evaluates seventy saved candidates discarded for exhausted functional-validation slots (37), reaching the turn limit before validation (31), or missing a post-edit probe rerun (two). Without regenerating patches, 39 pass public functionality, eighteen fail, and thirteen remain unresolved. Nine pass security, comprising eight preserved successes and one conversion. This motivates reserving final public-validation capacity and reusing validation only for an identical patch. Recovery records remain separate from original outcomes, so these counterfactual successes do not retroactively improve the reported campaign scores.

We compare retained diffs, reference patches, and official failing assertions on fifteen tasks outside the diagnostic cohort, fourteen from DeepSeek and one from Gemini, with functional success before and after editing (Table~\ref{tab:taxonomy}). Four patches address the wrong property. An Aiohttp repair changes session-key handling while leaving expiry unresolved, and a FastAPI repair limits body size instead of enforcing media-type-dependent parsing. Nine patches identify a relevant vulnerability class but leave the fix incomplete. Streamlit normalizes lexical paths without resolving symlink escape, while Airflow Hive validates an explicit schema but omits a connection-inherited value. Waitress repairs some transfer-encoding combinations but leaves malformed content-length behavior. JWCrypto checks decompressed size only after memory has been allocated. The remaining two patches implement the wrong failure behavior, using the wrong NumPy exception for an empty axis or leaving Markdown-it-py's malformed-byte decoding contract unsatisfied. These cases show why a plausible edit to the correct function still requires the full input, lifecycle, and error contract.

Operational errors remain separately observable. Gemini records 205 repair errors, comprising 153 \code{blockReason: OTHER} responses, 45 JSON decoding errors, six HTTP 500 errors, and one other value error. DeepSeek records 107, comprising 63 stop interruptions, 32 HTTP 429 responses, nine deadlines, two value errors, and one connection error. Provider labels are not assigned inferred causes. Bounded transport retries retain billing reservations, and completed responses are not regenerated. An errored cell can still have an officially evaluated retained candidate or no-op in the matched analysis.

\rqfinding{RQ4 Finding}{Losses arise during diagnosis, validation scheduling, semantic repair, and provider execution. Linking actions, patches, and terminal test outcomes distinguishes the engineering intervention each failure needs.}
